# Task 4 (bonus) — A/B промптів

Та сама задача («лічильник активних нотаток»), два формулювання промпта.

## Промпт A — базовий

> Додай лічильник активних задач до списку нотаток.

## Промпт B — структурований

> Контекст: Next.js 15 App Router, `TodoList.tsx` (client component), тип
> `Todo { id, title, done }`.
> Задача: показати «Активних: N» — кількість невиконаних нотаток.
> Обмеження: не зберігай похідне значення в `useState`, рахуй через `useMemo`;
> оновлення миттєве; без нових залежностей.
> Acceptance: при позначенні нотатки виконаною лічильник зменшується.

## Порівняння

| Критерій             | Промпт A                          | Промпт B                         |
| -------------------- | --------------------------------- | -------------------------------- |
| Ітерацій до прийняття | 3                                 | 1                                |
| Якість               | завів окремий `useState`, дублював стан | одразу `useMemo`, похідний стан |
| Output токени (≈)    | ~2 400                            | ~900                             |
| Правки a11y/типів    | довелось просити окремо           | врахував одразу                  |

## Висновок

Структурований промпт (контекст + обмеження + acceptance criteria) дав робочий
результат **з першої спроби** і втричі менше output-токенів. Час на формулювання
B (≈1 хв) окупився заощадженими ітераціями. Висновок: інвестиція в чіткий промпт
дешевша, ніж серія уточнень на «базовому» формулюванні.
