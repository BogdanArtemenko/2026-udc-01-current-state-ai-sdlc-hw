# Task 2 — Фіча через режими (Plan → Agent)

Фіча: **список нотаток** з можливістю позначати виконані та лічильником активних
(`app/components/TodoList.tsx`, підключено в `app/app/page.tsx`).

## Acceptance criteria

- [x] Поле вводу + кнопка «Додати» створюють нову нотатку (порожні/пробільні ігноруються).
- [x] Кожна нотатка має чекбокс; позначена — закреслена і приглушена.
- [x] Лічильник «Активних: N» рахує лише невиконані й оновлюється миттєво.
- [x] `npm run dev` стартує без помилок, `npm run build` проходить.
- [x] Без `any`, інтерактив у клієнтському компоненті (`"use client"`).

## Plan mode

Спочатку працював у **Plan**: попросив агента запропонувати структуру без запису коду.
План, який він повернув:

1. `Todo` тип `{ id, title, done }`, стан у `useState<Todo[]>`.
2. Похідний `activeCount` через `.filter().length` у тілі рендера.
3. Один компонент `TodoList`, форма + список.

### Що скоригував після рев'ю плану

- План тримав `activeCount` в окремому `useState` і оновлював у кожному хендлері —
  **прибрав**: це похідний стан, рахуємо через `useMemo` під час рендера (правило
  скіла vercel-react-best-practices «no derived state in useState»).
- Початково клік був на `<div>` — замінив на семантичні `<label>`+`<input type="checkbox">`
  і додав `aria-label` для поля вводу (a11y).
- Зафіксував межу: **без бекенду/БД** — стан живе в клієнті (записав у `app/AGENTS.md`).

## Agent mode

Після узгодженого плану перемкнувся в **Agent**: він згенерував компонент, підключив
до `page.tsx`, виправив типи. Знадобилось 2 ітерації — друга прибрала зайвий
`useCallback`, який не давав виграшу.
